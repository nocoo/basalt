## 1. 为什么做 2.0

Basalt 现在是 private Vite SPA（无 `exports`）。视觉语言被家族大量复制，没有共享代码。

| 现象 | 证据 |
|------|------|
| 本机产品 UI 复制皮肤 | `ai-arsenal` `backy` `bat` `dove` `fundly` `gecko` `lyre` `meowth` `pew` `raven` `surety` `xray` `zhe` 等有 `L0 body` 或 `ui/button.tsx` |
| 控件文件重复 | `personal/` 内约 308 个 `components/ui/*.tsx`；`ui/button.tsx` 15 份、15 个 hash |
| 壳分叉 | `app-shell.tsx` 14 份 14 个 hash。本仓库是 `DashboardLayout.tsx`，没有 `app-shell.tsx` |
| 新 clone 仍在用 | `otter` `pika` `ellie` `noheir` `signoff.now` `steed` `arena` 等 |
| 零跨仓依赖 | 无项目 import 公共 Basalt |

家族文档称本仓库为 **Gen 1 源**，surety / meowth 为 **Gen 2 活样本**（四层亮度、三文件壳、焦点归还）。见 `meowth/docs/features/02-dashboard-redesign-to-basalt-gen2.md`。

**不要把「Gen」当成一种皮肤。** 能力拆开写在第 12 节。本站现状：内容区已经是浮岛；侧栏仍是 Gen 1 单体。**亮度对齐 raven（§3.6）**。

2.0：本仓库变成库的第一消费者，再发 `@nocoo/basalt`，其它项目以后再替换拷贝。

## 2. 目标与非目标

### 2.1 目标

1. npm 包 `@nocoo/basalt`：ESM、granular export、可 tree-shake、CSS 可被 Vite 与 Next 消费。
2. 本仓库同时是展示站：控件文档 + 现有组合页。
3. 已有路由**不**做像素冻结。实现后由哥按 Basalt 视觉精神验收；允许比现网更好（见 3.2）。
4. Kumo 有的职责，manifest 里必须有对应行（实现、合并或明确排除）。
5. 实现时从家族挑 API 底稿；视觉跟 Basalt 精神走，哥验收。
6. 先控件后壳；每个控件完成即接线，不是攒到最后。

### 2.2 非目标（2.0 不做）

- 不迁其它产品仓。
- 不把 Radix 换成 Base UI。
- 不上 Figma、视觉回归 Worker、CLI `basalt add`。
- 不把本站壳改成 meowth 三文件 `app-shell` / `sidebar-context`。
- 不把 shadcn 薄包装直接当稳定 API。
- 不把 ActionGrid、登录工牌当 2.0 稳定控件（当 block 或留 app）。
- 不做地图控件（Kumo `BubbleMap` / `ChoroplethMap` 明确 **exclude**）。
- DataTable **做**（可比 Kumo 多）：catalog + optional peer，不进根 barrel。

## 3. 原则

### 3.1 站 = 控件文档 + 组合展示

| 层 | 2.0 | 现在 |
|----|-----|------|
| 控件文档 | **每个最终公开出口**一条 `/ui/:name` 页。侧栏只挂分类索引，不把出口平铺进顶层 nav | `/components` 等不能 copy |
| 组合展示 | 现有 dashboard / accounts / 场景 / login，逐步改 import 包 | 写死 mock 的 `*Card` |

侧栏视觉与分组容器继续用 `AppSidebar.tsx`。文档入口**不**给每个控件一条顶层 nav。改为：

- 现有分组不动（含已有 `nav.controls`「控件」：Interactive / Data / Forms / Navigation）
- 侧栏两大分区：**示例**（现有分组原样）+ **控件库**（Home + 每个 6.2 出口一条导航，默认展开，不折叠）
- ⌘K 能搜到控件文档

新增分组是已有壳上**唯一允许的导航变化**（第 13 节拍板）。

### 3.2 视觉精神（哥验收）

**不冻现网像素。** 现有控件、组合页不必长得和现在一模一样。实现时按 Basalt 视觉精神做；允许进化得更好。**变没变、好不好，哥验收时说了算。** 2.0 不做截图矩阵、不做像素 diff、不设 Wave B。

仍禁止（架构，不是像素门）：

- 不把本站壳换成 meowth 三文件 `app-shell` / `sidebar-context`（§2.2）。内容区浮岛可以留、也可以在验收里改得更像 Basalt，结构不换三文件。
- Button 默认 `h-9`、`h-10` 只当非默认 `size`（第 13 节第 11 条，这是 API，不是「现页截图像素」）。

允许：新文档路由；侧栏两大分区（示例 / 控件库），控件库默认展开。

接到现页时直接换实现，不必用 `className` 把旧像素抠回去。

### 3.3 发 npm 包

包名 `@nocoo/basalt`。

Tailwind 消费方（与 Kumo 相同，顺序硬性）：

```css
@source "../node_modules/@nocoo/basalt/dist/**/*.{js,jsx,ts,tsx}";
@import "@nocoo/basalt/styles/tailwind";
@import "tailwindcss";
```

非 Tailwind：

```ts
import "@nocoo/basalt/styles/standalone";
```

组件：

```ts
import { Button } from "@nocoo/basalt/components/button";
```

根 barrel **不含图表**，避免 `import { Button }` 拉到 recharts。图表走 `@nocoo/basalt/charts/donut`。

本仓库 workspace 自吃。开发期可 alias 到源码，但 **发布门必须用打包 tarball 在仓外 tmp 跑 A/B/C/D**（见 5.3）。Alias 不能代替门。

可参考：控件切分、compound、可机器读 variants、**文档站页结构**（`kumo-ui.com`）、components vs blocks。

不可抄：`bg-kumo-*`、Phosphor、Base UI 视觉、ECharts。产品壳不抄 Kumo 侧栏 IA。**文档站**对照 Kumo docs 复刻（§8），不是产品 Dashboard 侧栏。

### 3.6 亮度（对齐 raven）

对照 raven `docs/22-dashboard-design-system.md` + `globals.css`。三层持久表面；popover 只给浮层。

| 层 | 角色 | Token | Light | Dark |
|----|------|-------|-------|------|
| L0 | 侧栏、页底 | `--basalt-background` | 94% | 9% `#171717` |
| L1 | 浮岛 | `--basalt-card` | **97%** 浅壳 | 10.6% `#1b1b1b` |
| L2 | 数据卡、表格、Input、outline/secondary Button | `--basalt-secondary` | **99%** 读作白 | 12.2% `#1f1f1f` |
| 浮层 | Tooltip / menu | `--basalt-popover` | 100% | 10.6% |

硬规则：

- L2 是 **99% 近白**，不是 94% 灰卡（灰卡发脏）。raven 原话：secondary 读作 white，card 才是中性浅壳。
- Input / 表 / secondary·outline 用 `bg-basalt-secondary` + 边，和 L2 卡同底，靠 border 分。
- 禁止 Input 用 `bg-basalt-background`（94% 叠在白卡上像 disabled）。
- L1 浮岛保持 `bg-card`（97%），不要把岛和卡做成同一色。

验收页：`/ui/button`。

## 5. 仓库与发布面

### 5.1 目录

```
basalt/
  packages/basalt/                 # @nocoo/basalt
    package.json
    src/index.ts                   # 根 barrel：不含 charts
    src/styles/
      tokens.css                   # --basalt-* 与 light/dark
      tailwind.css                 # @theme 映射，供 Tailwind 消费方
    src/components/<name>/
    src/charts/<name>/             # 不进根 barrel
    src/providers/theme.tsx
    src/providers/link.tsx
  fixtures/
    vite-tailwind/                 # 模板，复制到仓外 tmp 跑门 A
    vite-standalone/               # 模板，复制到仓外 tmp 跑门 B
    next19/                        # 模板，复制到仓外 tmp 跑门 C（React 19）
  src/                             # 展示站
```

granular 路径统一 `@nocoo/basalt/components/<name>`；图表 `@nocoo/basalt/charts/<name>`。不要混用两种「控件根路径」。

### 5.2 CSS 与主题

只抽 `:root` **不够**。还要字体、keyframes、chart/heatmap 变量。全部进 **basalt 命名空间**：

| 种类 | 包内允许 | 禁止 |
|------|----------|------|
| 色 / 边 / 圆角 | `--color-basalt-*`、`--radius-basalt-card`、`--radius-basalt-widget`、`--radius-basalt-lg/md/sm`；utility `bg-basalt-*` `text-basalt-*` `border-basalt-*` `rounded-basalt-card` `rounded-basalt-widget` | `--color-background`、`.bg-background`、无前缀 `rounded-card` |
| 字体 | `--font-basalt-sans`、`--font-basalt-display`、`font-basalt-sans`、`font-basalt-display` | 包内 `font-display` / `font-sans` 无前缀 |
| 动画 | `@keyframes basalt-accordion-down` 等、`animate-basalt-*` | 无前缀 `accordion-down`、裸用 `tw-animate-css` 全局名 |

包的 `@theme` **只**注册 `--color-basalt-*`、`--radius-basalt-*`、`--font-basalt-*`、`--animate-basalt-*`。G1 与后续 lint 按此执行。

Showcase 现页仍用 `bg-background`：只在 **showcase 自己的 CSS** 里做映射，不进包：

```css
@source "../packages/basalt/src/**/*.{ts,tsx}";
@import "@nocoo/basalt/styles/tailwind";
@import "tailwindcss";
:root {
  --background: var(--basalt-background);
  /* 仅 showcase：让旧页 bg-background 继续工作，直到被替换 */
}
```

顺序与 §3.3 相同（硬性）：`@source` → basalt styles → `tailwindcss`。basalt `@theme` 必须在 `@import "tailwindcss"` 之前注册。Showcase 的 `@source` 指向 workspace 源码；消费方指向 `node_modules/.../dist`。

消费方两种契约（阶段 0 写入包 README，缺一不算阶段 0 完成）：

1. Tailwind：`@source` + `@nocoo/basalt/styles/tailwind`，peer `tailwindcss` ^4。`exports["./styles"]` **指向 tailwind**（与 Kumo 默认一致）。
2. 非 Tailwind：`@nocoo/basalt/styles/standalone`。standalone **不含 Preflight、不含 html/body reset**，只含 tokens + 控件用到的 utility + keyframes。

`data-mode` 与 `.dark` 都认。

**双契约验收（发布门必跑，不能「或」）：**

- Fixture A：干净 Vite + Tailwind + `@source`，不装 standalone。Button 计算色来自 `--basalt-*`。
- Fixture B：干净 Vite **不装 Tailwind**，只 import standalone。Button 同样有宽高和颜色。
- 门 A 与门 B 的 `computed style` 都要断言，不能只断言「有样式」。

### 5.3 构建、exports、依赖

| 项 | 决定 |
|----|------|
| 模块 | ESM only |
| 类型 | 必须产出 `.d.ts`（`vite-plugin-dts` 或等价） |
| `"use client"` | 每个组件 chunk 打 banner |
| `exports["."]` | **仅 stable 叶子 + provider**（不含 charts、不含 DatePicker、不含 catalog） |
| `exports["./components/*"]` | stable + catalog |
| `exports["./providers/*"]` | ThemeProvider、LinkProvider |
| `exports["./charts/*"]` | 仅图表 |
| `exports["./styles"]` | = `styles/tailwind` |
| `exports["./styles/tailwind"]` `./styles/standalone` | 见 5.2 |
| `files` | `dist`、`README`、`LICENSE`、`CHANGELOG`、`NOTICE`（若复制了 Kumo 逻辑） |
| `sideEffects` | 仅 `*.css` |
| `publishConfig.access` | public（第 13 节确认 org） |
| 许可证 | MIT（与本仓库一致）。复制 Kumo 的文件保留 Cloudflare MIT 于 NOTICE |
| `prepublishOnly` | build + 包内 jsdom 测试 + **browser 测试** + publint + **仓外 tarball 门 A/B/C/D**。必须作为 `packages/basalt/package.json` 的 npm lifecycle 写入仓库（02 Wave 8 独立 commit），禁止只写在文档里口头跑 |

**依赖归属（不再写「或」）：**

| 包 | 归属 |
|----|------|
| `react` `react-dom` | peer `^19`（与本仓库 React 19.2 对齐）。**不**宣称 18。门 C 只用 `fixtures/next19` 复制到仓外 tmp |
| `lucide-react` | peer |
| `tailwindcss` | optional peer ^4 |
| `@radix-ui/*` `class-variance-authority` `clsx` `tailwind-merge` `cmdk` `sonner` | **dependencies，不 bundle** |
| `recharts` | optional peer；**禁止**出现在根 barrel |
| `react-day-picker` | optional peer；DatePicker **只**从 `./components/date-picker` 导出，禁止进根 barrel |
| `@tanstack/react-table` | optional peer；DataTable **只**从 `./components/data-table` 导出，禁止进根 barrel |
| `i18next` | 不进包 |

catalog：**发布、随同一 semver**，只走 granular，不进根 barrel。catalog 的 6.2 `wire` **就是** `/ui/:name`，不要求现页已有实例。stable / chart / provider 的 `wire` 必须是**现在就能打开的组合页**（`/` `/health` `/network` 等，不是尚未创建的 `/ui/:name`）。破变更仍走 major。

**体积分层：** 根 barrel 只放小型 stable 叶子 + provider。heavy 控件只 granular + optional peer，未装 peer 时根入口不得拉到它们：图表 / `recharts`；DatePicker / `react-day-picker`；DataTable / `@tanstack/react-table`。可以比 Kumo 多出口（DataTable）。

**测试：** `packages/basalt/**/*.test.tsx` 必须跑。browser 测试（Dialog 焦点、Combobox、DatePicker、Sidebar、CommandPalette）列入 `prepublishOnly` 与阶段 8。

## 12. 本站 vs 家族后续（能力矩阵，不是一代标签）
