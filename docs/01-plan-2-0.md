> 状态：草案，待审查。未批准前不改业务代码。
> 当前版本：`package.json` → `1.3.5`。2.0 落地后升 **2.0.0**。
> 参考实现：`/Users/nocoo/workspace/references/kumo`（MIT，`@cloudflare/kumo` 2.12.0）
> 消费方摸底：本机 `~/workspace/personal/` 下 15+ 个已落地产品 UI，外加新 clone 的 Vite/Next 仓。

本文是 Basalt 从「视觉模板 / 演示站」变成「可 npm 安装的控件库 + 控件文档/组合展示站」的唯一口径。审查只改这篇；通过后再按提交计划动代码。

## 1. 为什么做 2.0

Basalt 现在是 private Vite SPA（`package.json` `"private": true`，无 `exports`）。视觉语言（哑光、亮度分层、`rounded-card`）已经被家族项目大量复制，但**没有一份共享代码**。

已核实的规模：

| 现象 | 证据 |
|------|------|
| 本机产品 UI 复制皮肤 | `ai-arsenal` `backy` `bat` `dove` `fundly` `gecko` `lyre` `meowth` `pew` `raven` `surety` `xray` `zhe` 等均有 `L0 body` 或 `ui/button.tsx` |
| 控件文件重复 | `personal/` 内约 **308** 个 `components/ui/*.tsx`；`ui/button.tsx` **15 份、15 个不同 hash** |
| 壳也分叉 | `app-shell.tsx` **14 份、14 个不同 hash**。当前本仓库仍是 Gen 1 的 `DashboardLayout.tsx`，没有 `app-shell.tsx` |
| 新 clone 仍在用 | `otter` `frogie` `pika` `life.ai` `ellie` `noheir` `dotty` `wooly` `signoff.now` `steed` `arena` 等带 `L0 body` 或 `app-shell` |
| 零跨仓依赖 | 没有任何项目 `import` 公共 Basalt 包；`@bat/ui` `@bogo/ui` 只是仓内包 |

家族文档已经把本仓库叫 **Gen 1 源**，把 surety / meowth 叫 **Gen 2 活样本**（四层亮度、浮岛、`app-shell` / `sidebar` / `sidebar-context`）。见 `meowth/docs/features/02-dashboard-redesign-to-basalt-gen2.md`。

2.0 要结束「约定 + 复制文件」。本仓库先变成库的第一消费者，再发布 `@nocoo/basalt`，其它项目随后替换各自的拷贝。

## 2. 目标与非目标

### 2.1 目标

1. **一个 npm 包** `@nocoo/basalt`：版本化、可 tree-shake、带 CSS tokens。
2. **本仓库同时是展示站**：每个控件有文档页（预览 + 可复制用法 + props）；现有场景页保留为**组合展示**。
3. **本站已有路由的界面效果不变**。用控件把现在的页面重新拼出来，观感与 1.3.5 一致。
4. **控件清单与 Kumo 对齐**：Kumo 有的控件，我们有同名职责的对应物。API 与分层可以参考 Kumo；像素、token、容器、sidebar **只用我们的**。
5. **实现时从家族里挑最好的一份当底稿**，再收成标准控件。不从零发明，也不把本仓库里写死 mock 的 `*Card` 直接当 API。
6. **先控件、后框架**：控件全部进包并在文档页可演示之后，再用这些控件拼回 `DashboardLayout` / 现有页面。

### 2.2 非目标（2.0 不做）

- 不把其它产品仓迁到 `@nocoo/basalt`（那是发布之后的跟进）。
- 不换 Primitive 引擎（不把 Radix 换成 Kumo 的 Base UI）。换引擎几乎无法保证观感冻结。
- 不上 Figma 插件、视觉回归 Worker、CLI `basalt add`。CLI / blocks 拷贝是 2.x 以后的事。
- 不把本站改成 Gen 2 浮岛布局。浮岛是家族后来的分叉；2.0 冻的是**本站现状**。
- 不发布 shadcn 的薄包装并称之为「Basalt Button」。进包的必须是有 Basalt token、有稳定 props、无业务 mock 的控件。

## 3. 五大原则（执行时逐条对照）

### 3.1 站 = 控件 + 组合展示

参考 Kumo：`kumo-ui.com` 既有 `/components/button`，也有 blocks / 组合示例。

本站对应两层：

| 层 | 2.0 之后 | 现在 |
|----|----------|------|
| 控件文档 | 每个进包控件一条路由，预览 + snippet + props | `/components` `/forms` `/interactive` 只是橱窗，不能 copy |
| 组合展示 | 现有 dashboard / accounts / wearable / banking / network / login 等，**改用进包控件拼**，数据仍走 mock + viewmodel | 页面内联图表、写死 Food/Transport 的 `DonutChartCard` |

侧栏**结构、视觉、分组容器**继续用本站现有 `AppSidebar`（`src/components/AppSidebar.tsx`），不换成 Kumo docs 的侧栏。允许**新增一个「控件」分组**挂文档路由——否则无法展示控件。已有分组与已有页面的样式、间距、图标笔画不得改。

### 3.2 界面效果不能变

约束范围：**已有路由**在 desktop / mobile 上的布局、颜色、圆角、字号、图表形状。

允许：

- 新增 `/ui/:component`（或同等）文档路由
- 侧栏多一组导航
- DOM 结构因 compound 组件变化，但计算后的视觉一致

不允许：

- 改 L0/L1/L2 的 HSL 值
- 给 L2 卡加回 `border` / `shadow`（当前卡片靠亮度，不靠描边）
- 把 Inter / DM Sans / 1.5px stroke 换成 Phosphor 或 Kumo 字号体系
- 为了「更像 Kumo」改 Button 默认尺寸导致现有页按钮变高

验收：每个被重写的已有页面，对照 1.3.5 的截图或人工并排；有出入就算没完成。

### 3.3 发 npm 包供其它项目复用

包名：`@nocoo/basalt`（与 `@nocoo/surety` `@nocoo/bogo` 同一 scope）。

消费方式（目标，对齐 Kumo 主路径，而不是 shadcn 拷文件）：

```tsx
import { Button, StatCard } from "@nocoo/basalt";
import "@nocoo/basalt/styles";
```

也提供 granular：`@nocoo/basalt/components/button`。

本仓库用 bun workspace 自吃同一份源码，不发布后再从 npm 拉回来开发。

### 3.4 对齐 Kumo 的控件面，用我们的皮

Kumo 是 MIT。可以参考：

- 控件切分（什么算 Button，什么算 Field，什么算 Block）
- compound API（`Dialog.Trigger` / `Dialog.Title`）
- variants 可被机器读（`KUMO_*_VARIANTS` 那种结构，我们用 `BASALT_*_VARIANTS`）
- 文档页结构（Installation / Usage / Examples / Props）
- components vs blocks 的所有权（进包 vs 拷走）

不可以抄：

- `bg-kumo-*` / Phosphor / Base UI 视觉
- Kumo 的 sidebar 信息架构
- ECharts 皮肤（本站图表是 Recharts + `src/lib/palette.ts`）

品牌替换：Kumo `CloudflareLogo` → 我们的 `BasaltMark`（现有 `Mountain` 图标语言），不是 Cloudflare 标志。

### 3.5 执行顺序：先控件，后框架

```
tokens 进包
  → 逐个控件（实现 + 单测 + 文档页）
    → 控件清单清零
      → 用控件拼回 DashboardLayout / AppSidebar / 现有页面
        → 本站自吃稳定
          → 发布 @nocoo/basalt@2.0.0
```

禁止：先拆 monorepo 再让页面空白；禁止「先改完壳再补控件」。壳是最后用控件拼回来的框架。

## 4. 分层模型

直接采用 Kumo 的责任划分，名称用我们的。

| 层 | 含义 | 交付 | 2.0 是否做 |
|----|------|------|-----------|
| Tokens | L0/L1/L2、chart、radius、字体 | CSS，随包 | 做。从 `src/index.css` 抽出，语义名可保留现有 `background/card/secondary`，文档里写明与 L0/L1/L2 的对应 |
| 控件 Components | 无业务数据、无 i18n 泄漏 | `@nocoo/basalt` import | 做。本文第 6 节清单 |
| 块 Blocks | 有布局假设的配方（PageHeader、登录工牌） | 2.0 仍放展示站；不发 CLI | 不做 CLI。登录页等先留在 app |
| 展示 Showcase | 文档页 + 现有组合页 | 本仓库 SPA | 做 |

原则与 Kumo `components-vs-blocks.mdx` 相同：先当 block，复用被证明再进包。2.0 例外：Kumo 已列为 component 的，我们直接当 component 做，避免家族再分叉一份 Button。

## 5. 仓库结构（2.0 目标）

在**本仓库内**拆 workspace，不另开 git repo。

```
basalt/
  package.json                 # 工作区根，showcase 脚本仍是 bun dev
  packages/
    basalt/                    # 发布名 @nocoo/basalt
      package.json             # name, exports, files, peerDependencies
      src/
        index.ts               # barrel
        styles/tokens.css      # 从现 index.css 抽出的 token
        components/<name>/     # 一控件一目录
        charts/<name>/
        utils/cn.ts
      src/**/*.test.tsx
  src/                         # 展示站（现有 app）
    pages/                     # 组合展示 + 控件文档页
    components/                # 只留 app 壳与文档页自己的胶水，控件从包 import
    data/ mock viewmodels      # 仍属 app
  docs/
    README.md
    01-plan-2-0.md             # 本文
```

`peerDependencies`：`react` `react-dom`。图标继续 `lucide-react`（本站 1.5px stroke）。图表 `recharts` 作 optional peer，只在 import 图表控件时需要。

构建：Vite library mode 打 ESM + d.ts；CSS 走 `exports["./styles"]`。showcase 用 workspace `"@nocoo/basalt": "workspace:*"`。

开发期允许 showcase 直接 alias 到 `packages/basalt/src`，避免每改一个控件都先 build。

## 7. 每个控件怎么实现：选底稿的流程

家族里同一控件有十几份互不相等的拷贝。2.0 **禁止**闭眼用本仓库 `ui/`，也 **禁止**闭眼用 Kumo 源码换皮。每个控件开工前走同一套比选，结果写进该控件文档页的「来源」一节。

### 7.1 比选步骤

1. **读 Kumo**：API 形状、compound 切分、variants 轴、a11y 约束（例如 icon-only 强制 `aria-label`）。路径：`references/kumo/packages/kumo/src/components/<name>/` 与对应 mdx。
2. **搜家族**：`fd` / `rg` 在 `~/workspace/personal/*`（排除 `node_modules` `.git` `coverage` `dist`，排除第三方 fork：`manifest` `multica` `eagle-webui` `workany`）。
3. **打分**（高到低）：
   - 与本站 1.3.5 视觉能否无缝替换（token、圆角、无边框 L2）
   - 是否数据/文案 props 化，有没有 i18n / mock 泄漏
   - a11y（label、键盘、Radix 是否正确）
   - 是否有测试
   - API 是否接近 Kumo（越近越好，但视觉冲突时视觉优先）
4. **定底稿**：一家赢家 + 可摘的 runner-up 片段。输家路径记在文档，避免以后又抄回去。
5. **实现**：底稿迁入 `packages/basalt/src/components/<name>/`，token 换成包内语义 class，补 `BASALT_*_VARIANTS`、测试、文档页。
6. **本站先不改组合页**。只加文档路由。拼框架阶段再替换。

## 10. 原子化提交计划

每个提交只含一个逻辑变更，conventional commits，全小写，≤50 字符。提交后可 lint / 可测 / 站可跑。

建议类型与粒度：

| 阶段 | 提交粒度 | 例子 |
|------|----------|------|
| 0 | 基础设施各一次 | `chore: add packages/basalt workspace` → `feat: extract design tokens into package` |
| 1–6 | **一控件一提交** | `feat: add basalt Button`（含实现、测试、文档页、barrel export） |
| 7 | 一页或一壳一提交 | `refactor: rebuild accounts page with package` |
| 8 | 发布相关各一次 | `chore: release v2.0.0` |

禁止 `git add -A`。删除无引用死代码随该次提交走。

不在 2.0 计划里混进无关依赖升级。

## 11. 6DQ 质量计划
