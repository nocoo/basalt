## 1. 为什么做 2.0

Basalt 现在是 private Vite SPA（无 `exports`）。视觉语言被家族大量复制，没有共享代码。

| 现象 | 证据 |
|------|------|
| 本机产品 UI 复制皮肤 | `ai-arsenal` `backy` `bat` `dove` `fundly` `gecko` `lyre` `meowth` `pew` `raven` `surety` `xray` `zhe` 等有 `L0 body` 或 `ui/button.tsx` |
| 控件文件重复 | `personal/` 内约 308 个 `components/ui/*.tsx`；`ui/button.tsx` 15 份、15 个 hash |
| 壳分叉 | `app-shell.tsx` 14 份 14 个 hash。本仓库是 `DashboardLayout.tsx`，没有 `app-shell.tsx` |
| 新 clone 仍在用 | `otter` `pika` `ellie` `noheir` `signoff.now` `steed` `arena` 等 |
| 零跨仓依赖 | 无项目 import 公共 Basalt |

家族文档称本仓库为 **Gen 1 源**，surety / meowth 为 **Gen 2 活样本**（四层亮度、三文件壳、焦点归还）。见 `meowth/docs/features/02-dashboard-redesign-to-basalt-gen2.md`。

**不要把「Gen」当成一种皮肤。** 能力拆开写在第 12 节。本站现状：内容区已经是浮岛；侧栏仍是 Gen 1 单体；亮度注释是 L0/L1/L2，不是 L0–L3。

2.0：本仓库变成库的第一消费者，再发 `@nocoo/basalt`，其它项目以后再替换拷贝。

## 2. 目标与非目标

### 2.1 目标

1. npm 包 `@nocoo/basalt`：ESM、granular export、可 tree-shake、CSS 可被 Vite 与 Next 消费。
2. 本仓库同时是展示站：控件文档 + 现有组合页。
3. **已有路由**在批准基线 commit 上的观感冻结（见 3.2）。
4. Kumo 有的职责，manifest 里必须有对应行（实现、合并或明确排除）。
5. 实现时从家族挑 API 底稿，视觉以本站基线为准。
6. 先控件后壳；每个控件完成即接线，不是攒到最后。

### 2.2 非目标（2.0 不做）

- 不迁其它产品仓。
- 不把 Radix 换成 Base UI。
- 不上 Figma、视觉回归 Worker、CLI `basalt add`。
- 不把本站壳改成 meowth 三文件 `app-shell` / `sidebar-context`。
- 不把 shadcn 薄包装直接当稳定 API。
- 不把 TanStack DataTable、ActionGrid、登录工牌当 2.0 稳定控件（当 block 或留 app）。
- 不做地图控件（Kumo `BubbleMap` / `ChoroplethMap` 明确 **exclude**）。

## 3. 原则

### 3.1 站 = 控件文档 + 组合展示

| 层 | 2.0 | 现在 |
|----|-----|------|
| 控件文档 | 稳定 API 各有文档；catalog 项可共用索引页 | `/components` 等不能 copy |
| 组合展示 | 现有 dashboard / accounts / 场景 / login，逐步改 import 包 | 写死 mock 的 `*Card` |

侧栏视觉与分组容器继续用 `AppSidebar.tsx`。文档入口**不**给每个控件一条顶层 nav（74 条不可用）。改为：

- 现有分组不动
- 新增一组 **「控件」**，默认折叠，里面是分类索引（动作 / 表单 / 浮层 / 图表…），点进 `/ui/:name`
- ⌘K 能搜到控件文档

新增分组是已有壳上**唯一允许的导航变化**（第 13 节拍板）。

### 3.2 观感冻结（可执行）

**基线 commit：** 计划批准时的 `HEAD`（当前工作区 `8089981` 仅作审查基线；批准时再钉一次）。没有 `v1.3.5` tag，不要写「对照 1.3.5 截图」除非先打 tag 或存截图。

**阶段 0 产出冻结夹：** `docs/baselines/2-0/`，矩阵 = 已有路由 × `{light,dark}` × `{desktop,mobile}`。可用 Playwright 截图或手存。阶段 7 对照这批图，不是对照记忆。

**冻什么：** 已有路由里，每个现成实例的布局、颜色、圆角、字号、图表形状、边框有无。

**不冻成「设计规范理想态」：**

- 禁止把全部卡改成无边 L2。`BulletChartCard` 现在就是 `border-border bg-card`（`src/components/dashboard/BulletChartCard.tsx`）。
- 禁止把 Button 默认从本站 `h-9` 改成 meowth `h-10`。
- 禁止把 Input 默认从本站 `bg-background rounded-md` 改成另一种表面，除非该实例本来就被页面 `className` 覆盖——覆盖的跟覆盖走，默认跟默认走。
- 本站内容区浮岛（`DashboardLayout.tsx` 约 122–123 行）**属于基线，要保留**。禁止改成 meowth `rounded-island` 的壳结构。

**允许：**

- 新文档路由
- 侧栏多一个默认折叠的「控件」组（若第 13 节同意）
- DOM 因 compound 变化，像素一致

**每个现页替换时的规则：** 该页现在用什么 class，替换后计算样式仍是那套。控件默认值可以是「规范表面」，但现页必须通过 `className` / variant **复现原样**，而不是把现页拽去规范。

### 3.3 发 npm 包

包名 `@nocoo/basalt`。

Tailwind 消费方（与 Kumo 相同，顺序硬性）：

```css
@source "../node_modules/@nocoo/basalt/dist/**/*.{js,jsx,ts,tsx}";
@import "@nocoo/basalt/styles/tailwind";
@import "tailwindcss";
```

非 Tailwind：

```ts
import "@nocoo/basalt/styles/standalone";
```

组件：

```ts
import { Button } from "@nocoo/basalt/components/button";
```

根 barrel **不含图表**，避免 `import { Button }` 拉到 recharts。图表走 `@nocoo/basalt/charts/donut`。

本仓库 workspace 自吃。开发期可 alias 到源码，但 **发布门必须用打包 tarball 在干净 Vite fixture 与 Next fixture 里安装**（见 5.3）。Alias 不能代替门。

### 3.4 对齐 Kumo 的面，用我们的皮

可参考：控件切分、compound、可机器读 variants、文档页结构、components vs blocks。

不可抄：`bg-kumo-*`、Phosphor、Base UI 视觉、Kumo 侧栏 IA、ECharts。

Kumo `CloudflareLogo` / `PoweredByCloudflare` → `BasaltMark`（本站 Mountain）。不实现 Cloudflare 标。

若源码级参考 Kumo，发布包 README 保留 Cloudflare MIT notice。

### 3.5 顺序

```
阶段 0：workspace + 冻结截图 + token/CSS 契约
  → 逐个控件：实现 + L1 测试 + 文档页 + 接到一条现页或 fixture
    → 稳定清单清零
      → 拼回壳与剩余组合页
        → tarball 门通过
          → 先发 2.0.0-alpha，自吃后再 2.0.0
```

壳仍最后换。叶子控件不准「做完只躺在 packages 里」。

## 5. 仓库与发布面

### 5.1 目录

```
basalt/
  packages/basalt/                 # @nocoo/basalt
    package.json
    src/index.ts                   # 根 barrel：不含 charts
    src/styles/
      tokens.css                   # --basalt-* 与 light/dark
      tailwind.css                 # @theme 映射，供 Tailwind 消费方
    src/components/<name>/
    src/charts/<name>/             # 不进根 barrel
    src/providers/theme.tsx
  fixtures/
    vite-app/                      # 发布门：干净 Vite
    next-app/                      # 发布门：干净 Next
  src/                             # 展示站
  docs/baselines/2-0/              # 冻结截图
```

granular 路径统一 `@nocoo/basalt/components/<name>`；图表 `@nocoo/basalt/charts/<name>`。不要混用两种「控件根路径」。

### 5.2 CSS 与主题

只抽 `:root` **不够**。还要：`font-display`、accordion keyframes、`tw-animate-css` 里控件真正用到的动画、chart/heatmap 变量。

Token **必须** `--basalt-background`、`--basalt-card`、`--basalt-secondary`… 全局 `--background` 会覆盖消费方（含 Gen 2 项目）。

Showcase：

```css
@import "@nocoo/basalt/styles/tailwind";
@source "../packages/basalt/src/**/*.{ts,tsx}";
@import "tailwindcss";
:root {
  --background: var(--basalt-background);
  /* 其余现有名映射，保证 bg-background 等现页 class 不变 */
}
```

消费方两种契约（阶段 0 写进包 README，缺一不算阶段 0 完成）：

1. Tailwind：`@source` + `styles/tailwind`，且 **peer `tailwindcss` ^4**
2. 非 Tailwind：`styles/standalone`（预编译控件用到的 utility）

`data-mode` vs `.dark`：本站现在是 `<html class="dark">`。包同时认 `.dark` 与 `[data-mode=dark]`，避免 Next 与本站两套。

### 5.3 构建、exports、依赖

| 项 | 决定 |
|----|------|
| 模块 | ESM only |
| 类型 | 必须产出 `.d.ts`（`vite-plugin-dts` 或等价）。Vite library mode **不会**自动长类型 |
| `"use client"` | 每个组件 chunk 打 banner，Next App Router 才能用 |
| `exports` | `.`、`./components/*`、`./charts/*`、`./styles`、`./styles/tailwind`、`./styles/standalone`、`./package.json` |
| `files` | `dist`、`README`、`LICENSE`、`CHANGELOG` |
| `sideEffects` | 仅 `*.css` |
| `publishConfig.access` | public（第 13 节确认 org） |
| `prepublishOnly` | build + 包内 test + publint/exports 检查 |

**依赖归属：**

| 包 | 归属 | 原因 |
|----|------|------|
| `react` `react-dom` | peer `^18 \|\| ^19` | |
| `lucide-react` | peer | 与 Kumo 对 Phosphor 相同 |
| `tailwindcss` | optional peer ^4 | 只对 Tailwind 消费方 |
| `@radix-ui/*` `class-variance-authority` `cmdk` `sonner` | **dependencies**（或打进 bundle） | 消费方不应手装 20 个 radix |
| `recharts` | optional peer | 只在 `charts/*` |
| `@tanstack/react-table` | **2.0 不进包** | DataTable 当 block，留 app |
| `react-day-picker` | optional peer | 只随 DatePicker |
| `i18next` | 不进包 | |

根 `index.ts` 不得静态 export 任何 `charts/*`。

**测试配置：** 现 `vitest.config.ts` 的 `include` 只有 `src/**`，coverage 只管 models/viewmodels。阶段 0 必须让 `packages/basalt/**/*.test.tsx` 跑起来。阶段 8 命令含 `typecheck`。

**发布门：** `npm pack` 的 tarball 安装进 `fixtures/vite-app` 与 `fixtures/next-app`（禁止 workspace alias）。断言：Button 有宽度/颜色；不装 recharts 时 `import { Button }` 成功；Next 能 SSR 一个不碰 `window` 的页。失败不准发。

复杂控件（Combobox、DatePicker、Dialog 焦点、Sidebar、CommandPalette）除 jsdom 外要有 **browser 测试**（Vitest browser 或 Playwright component），对齐 Kumo 对这类组件的做法。

## 7. 底稿流程

### 7.1 步骤（可复现）

1. 读 Kumo API（路径 + **kumo commit**，审查时为工作区当时 HEAD）。
